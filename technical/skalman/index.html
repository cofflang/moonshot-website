skalman

the interactive shell

skalman is moonshot's command line. it reads a line of keystrokes, echoes them to the screen and on Enter runs the named command. there is one shell session per kakel window, so a half-typed command survives switching focus away and back. a command's output lands in the window it was typed in. the window keeps its text when the layout changes, when a program opens beside it, when a window fills the screen and when the screen is locked.

editing a line

the arrow keys move within the line and up and down go through the history. home and end, or ctrl-a and ctrl-e, go to the ends of the line. ctrl-w deletes the word before the cursor, ctrl-k deletes to the end of the line and ctrl-u to the start. tab completes a command name or, after the first word, a file name. a second tab lists the candidates. double quotes keep spaces inside one argument, as in write "my file.txt" hello.

command reference

type help for the current list, or help (command) for what one command takes and does. arguments are written in parentheses, with optional ones in brackets. every path may contain slashes.

help [command]
shows the full command list, or what one command takes and does.
clear
clears the focused window.
echo (text)
prints its argument back. echo --file (path) prints a file's contents, however long the file is.
list (path)
shows the contents of a directory, with sizes and permissions.
change (path)
changes the current working directory.
make (name)
creates an empty file (name with a dot) or directory.
remove (name)
deletes a file or empty directory.
write (name) (text)
writes text into a file, creating it if needed.
copy (src) (dst)
copies a file. both paths may contain slashes.
rename (src) (dst)
renames or moves a file or directory across directories.
count (file)
prints lines, words and bytes in a file. a last line with no newline after it counts as a line.
where
prints the current working directory path.
zone [offset]
shows the local time and its offset from utc, 14:05, UTC+1. with an offset it sets it, zone +1, zone -3:30 or zone 5:45, from -24 to +24 hours. any logged in user may set it. it is saved in tid.zone. there is no summer time.
besikta
prints the memory map, the disk, the framebuffer and the processor the machine reports.
dvala [on | off | seconds]
the screen saver, see kakel.
sync [create]
saves the filesystem to a disk that carries moonshot's magic and says when a write failed. a file that changes while it runs may be saved half old and half new. sync create makes such a disk, after a typed confirmation.
mode (path) (level)
sets file permissions to public, private, or locked.
own (path) (user)
changes a file's owner. only root may do this.
whoami
prints the current user name.
login (name)
asks for the password at a masked prompt and switches the window to that user when it matches.
passwd [user]
changes your password after checking the old one, then asks for the new password twice. root may change another account's password without the old one.
adduser (name)
creates a new user. only root may. the user table is fixed-size.
eval (expr)
evaluates a c0 expression through the repl. eval -c uses the jit compiler.
interpret (file)
runs a c0 source file line by line through the repl interpreter.
edit (file)
opens a file in the skrift text editor, in a window of its own.
draw (file) [size]
opens a picture in the pensel pixel editor, in a window of its own.
start (program) [arguments]
runs a program from jakel in ring 3, in a kakel window of its own. the words after the name are its arguments, so start lira.elf mysong.not opens that song.
execute (file.c0)
compiles a c0 program with coff, links it with smed and starts it, all on moonshot. the program stays next to its source as file.elf, so start file.elf runs it again without compiling. an error stops it at the step that failed, with that step's own message. coff and smed are in the root as coff.elf and smed.elf. hello.c0 is there to try them on.
run (script.sk) [arguments]
runs a script, see scripts below.
tasks
lists every task in the scheduler table.
kill (id)
stops a task by the id tasks shows. only root, or the user the task runs as, may stop it.
split
adds a new window to the grid, logged in as the same user. the shell prompts the window whose line it just finished, so the prompt is back after split and after start.
close
removes the focused window and stops the program in a tavla, as alt-w does.

the repl

eval (expr) runs c0 statements through an interpreter, with variables that last for the session, if and else, while and for loops and print(). eval -c compiles them to machine code with the jit instead. interpret demo.c0 runs the demo file seeded on first boot.

scripts

a file ending in .sk is a script, run with run name.sk and its arguments, or by a click in hylla. each line is a shell command, a comment starting with #, name = expression or a block in braces the way c0 writes them. 

# count down, then start a program
n = 3
while (n > 0) {
    echo $n
    n = n - 1
}
if ($1 == "quiet") {
    echo starting quietly
} else {
    echo starting $1
}
start lira.elf $1

every value is a string. + - * / % and < > <= >= work on whole numbers, + joins anything else, == and != compare strings. && || ! and parentheses work as in c0. $1 to $9 are the arguments and $# how many there are. a script stops at the first line it cannot read, saying where. it also stops after 100000 lines run. at the prompt, name = expression and $name work too.

users

root and guest exist from the first boot, since raket asks for a login before anything is shown. adduser, passwd and login manage users, while own and mode set a file's owner and whether it is public, private or locked.

moonshot 0.6.0 and 0.6.1 did not keep users apart. login with no password switched to any account, several commands did not ask who was asking, a program took the rights of the window it was started from and passwords were typed on the command line and kept in the history. if you relied on either release to keep one user away from another, do not. 0.7.0 fixes this, within the limit in the next paragraph.

users are kept apart only for the length of one boot. users, passwords, owners and modes are not saved, so after a reboot every file belongs to root, every other user can read it and root has no password until passwd is run. everything below holds within one boot.

each program keeps the user it was started as. so do the programs and shell windows it starts. switching a shell window to root does not give root rights to programs already running as a guest. only root or the owner of a file may change it, including its mode, its name and its contents. a locked file refuses reads by other users. new files belong to the user who made them.

a password is typed at a masked prompt, with login (name) and passwd [user]. it is never part of a command line and never kept in the history. passwd asks for the old password, unless root runs it. adduser and own need root. history is kept per user, so up shows only the commands of the user of that window.

a user starts programs and scripts, runs interpret and builds with execute only from files that user or root owns, in folders that user or root owns. root therefore runs only root's own files. to run another user's program, take it over with own first. copying another user's text into a file of your own, including running a selection with F5 or F6 in skrift, is running it.

coff and smed read only files that the user who started them or root owns, in folders that the user or root owns, however they are started. root takes over another user's library with own before building with it.

eval, eval -c and interpret run in the kernel and need root. execute builds a program that runs in ring 3 with the user of whoever ran it. only root, or the user a task runs as, can stop it with kill. prompt variables belong to their user and window and are cleared when that window is replaced.

the person at the keyboard can use every open window, root's included. a window whose folder is removed goes back to / and says so. see raket and kakel.
