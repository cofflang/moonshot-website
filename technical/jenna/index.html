jenna

physical and virtual memory

jenna is moonshot's memory. it owns every physical page, carves small allocations out of big ones and keeps the page tables that decide what the addresses the kernel uses actually mean.

pages

the bottom layer hands out physical memory in 4096-byte pages, from the first usable region past the end of the kernel. a freed page goes onto a free list kept inside the freed pages themselves. an allocation takes from that list first, so freed memory is reused.

kernel heap

kmalloc and kfree sit on top, for the many small pieces of memory the kernel needs. every block has a small header with its size and whether it is free, allocation takes the first block that fits. a free merges the block with free neighbours. kfree refuses a pointer it never handed out and a block that is already free, loudly, since a quiet double free corrupts something unrelated much later.

page tables

jenna builds the kernel's page tables at boot from pages it allocated itself, mapping physical memory one to one. it also owns the page fault handler. one authorized boot probe can fault, receive a zeroed page and retry its instruction. other kernel faults halt unless they occur at a guarded user-copy site, where recovery ends the calling program. a fault in ring 3 also ends that program.

every ring-3 program runs on page tables of its own, with private mappings for its code, stack and heap. inherited kernel mappings stay supervisor-only and cannot be replaced by the user mapper. a failed mapping leaves the existing tree intact. when the program is gone, pt_free reclaims its owned pages and tables without freeing the shared kernel branches.
