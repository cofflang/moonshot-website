booting on hardware

a USB image and a first-boot checklist

moonshot boots through GRUB on BIOS or UEFI. its unsigned image needs Secure Boot disabled. a UEFI machine needs the framebuffer requested by the kernel because VGA text mode is unavailable there.

prepare the stick

from the moonshot source directory, run ./make_usb.sh --iso moonshot-usb.iso to build an image and print its hash without writing a device. keep that hash with your boot notes. the script puts the kernel's own kernel/core/grub.cfg on the stick, so GRUB starts moonshot at once instead of after a menu. the script stops if that file loses the video settings a UEFI machine needs. the kernel asks for 1024 by 768 at 32 bits and falls back to any mode the firmware offers.

insert the intended USB stick and run ./make_usb.sh /dev/sdX, replacing the path with that USB device. the script checks that the device is USB, asks you to type its name and verifies the image after writing it. --no-build reuses the existing kernel. record the hash printed by the writing run because a newly assembled ISO can have a different timestamp even when its kernel is identical.

boot and inspect

  1. open the firmware boot menu and choose the UEFI USB entry. on the IdeaPad, use F12. record whether GRUB reaches a visible login screen.
  2. log in as root with an empty password on a fresh boot. accounts and passwords live in memory and do not survive reboot.
  3. check letters, Shift, Backspace, arrows and Enter, then pointer movement and clicking. run besikta for the detected hardware.
  4. open hylla and an offline page in utsikt, then leave the machine running for a minute and check that input still responds.
  5. press F12 inside moonshot to show the boot log. record any blank screen, fault or driver failure together with the image hash.

disk behavior

normal filesystem writes require Moonshot magic on the supported ATA disk. an unrecognized disk is left untouched. a failed write is reported by sync instead of being counted as saved. sync create initializes that disk only after typed confirmation and is not part of this boot check. an I/O failure during sync can leave an incomplete filesystem because saving is not crash-atomic.

an emulated UEFI boot checks the image packaging and kernel entry path. it does not establish that the display, keyboard, touchpad or storage work on a physical laptop.
