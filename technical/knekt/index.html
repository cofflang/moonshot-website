knekt

the kernel

knekt is the kernel core. most of what the kernel does lives in the named parts around it, and knekt is the piece that wires them together.

boot

GRUB boots the kernel through Multiboot into a short piece of hand-written assembly, which sets up just enough of the machine to call knekt's main. main wakes the machine a piece at a time, the serial port, the framebuffer (punkt), the keyboard, memory (jenna), the interrupt table and the timer. then it tiles the screen into windows (kakel), starts a shell in each (skalman) along with the scheduler (chrone), and brings up the filesystem (jakel).

when things go wrong

a fault in a ring-3 program ends that program and nothing else. a fault in the kernel prints the vector, the error code, the faulting address and the instruction pointer over serial and halts. a fixed capacity in the kernel that fills up says so on the serial port rather than dropping work without a word.

ring 3

programs are static elf64 executables, usually read from jakel. each runs in ring 3 with page tables, a kernel stack and a heap of its own, and talks to the kernel through the syscall instruction. in coff's --elf mode a program reaches them through builtins such as win_info() and readfile().
